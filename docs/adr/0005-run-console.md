# ADR 0005: A run console with a live node canvas (React Flow over a run-event log)

*Status: proposed by Claude on 20 Nov 2026 for batch 4; Amir decides at the V6 gate.*

## Context

The capstone review passed. The reviewer still found the product hard to read from a demo, and engineering managers will judge it in minutes. A peer's research app (Astraeus) won attention with a live node canvas: each agent step lights up, shows a one-line result, a duration and a retry badge, and saved runs replay. governor already has two LangGraph graphs (build: 14 nodes, with an interrupt and two repair loops; ask: 11 nodes, with guard, validator and repair). Neither is visible today, except through Slack messages and LangSmith-style traces.

## Decision

1. **One event contract for runs** (`docs/capstone/batch4.md` §34): node-level JSONL logs written by a wrapper around each node. These are separate from the existing build events, so nothing that exists changes.
2. **One reducer, two implementations with shared test cases** (Python for the API, TypeScript for the UI).
3. **A read-only FastAPI router with Server-Sent Events** for live runs and paced replay.
4. **A React console in `apps/console/`:** React Flow for the canvas, dagre for layout, Recharts for charts.
5. **Shipped demo runs, generated by the real traced graphs with fakes,** so the console demos with no model calls.
6. **LangGraph Studio as a developer view** through `langgraph.json`, not as the product UI.

## Alternatives

- **LangGraph Studio / LangSmith only.** It costs nothing to build. But it is LangChain's debugger: it needs a LangSmith account, has no branding and no result views, and is not something to hand to a stakeholder.
- **Streamlit with Graphviz or streamlit-flow.** Cheap, but no smooth live animation, and Streamlit is being retired from governor's interfaces.
- **Polling, as in the peer repo.** Simpler, but slower and noisier. SSE is one-way, plain HTTP and enough here.
- **Writing to the existing build events.** That would change a contract Slack depends on, and ask has no events today.

## Consequences

- A second front-end toolchain (Node 20) appears in the repo. CI and Docker need a Node build stage.
- Run logs grow with every run. They are small (counts only), but a retention rule is a follow-up.
- Summaries must stay free of data values. A marker-string test guards it.
- When the console is unused, governor behaves exactly as before.
