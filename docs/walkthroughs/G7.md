# G7 walkthrough: API, auth and deployment

*Gate review, 23 Oct 2026. Drafted by Claude from the step's output; read, edited and approved by Amir.*

**What it is.** A FastAPI app (`src/governor/api/app.py`) over `governor.ask.service`: `POST /v1/ask`, `POST /v1/threads/{id}/resume` (answer a clarifying question), `GET /v1/traces`, `GET /v1/traces/{id}`, and `/health`. Docker and docker-compose run it; Streamlit (G8) and MCP (G9) are thin clients over the same service.

**Auth: the role comes only from the token.** `GOVERNOR_API_TOKENS` maps tokens to roles (`analyst:<token>,finance_admin:<token>`), set in `.env`, never committed. `caller_role()` compares the bearer token against every configured token with `hmac.compare_digest` and no early exit, so timing doesn't reveal which token is close. A request body that tries to send a `role` field is refused (422). Tokens are never logged.

**Ownership.** Threads and traces belong to the role that created them. Grok's first review found a leak: asking with another role's thread id returned "thread exists, resume it", which told the caller the thread existed. Fixed in loop 1, with a test that tries exactly that.

**Errors** are JSON `{error, code}` and never echo the input. The interactive docs pages are off.

**Deployment.** The image builds the warehouse, metadata store and catalog at build time and opens them read-only; it runs as a non-root user, and only `/data` (traces, checkpoints) is writable. `.env.example` holds placeholders only.

**Known gaps (for G10 / the README).** The checkpoint store on `/data` keeps the raw question and result rows even when trace text is off. `/openapi.json` is still served. Acceptance checks the Dockerfile by keywords and does not run `docker build`. Single tenant: shared role tokens, no user accounts, no rate limiting.

**What I would defend in an interview.** Why the role comes from the token and never from the request; why constant-time comparison; why ownership checks have to cover "does this exist" answers, not just reads.
