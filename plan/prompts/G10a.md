# G10a: Tune on the tune split, then freeze the prompts

Real models (OpenRouter key from the environment), tune split only. Budget: at most $2 for this step.

Do, in this order:
1. `uv run python -m governor.eval.run --system baseline --split tune --llm openrouter`, then the same for `--system agent`.
2. Fix agent problems you find on the tune split only: prompts in `src/governor/ask/prompts/`, retrieval settings, repair logic. Re-run the agent on tune after each change. Record every tune run's summary in NOTES, one line each (`ts system execution_accuracy valid_sql_final clarify_p/r policy_compliance pii_leak cost`).
3. Stop when two consecutive agent runs do not improve execution accuracy, or after 4 agent runs.
4. Freeze: write the sha256 of every file in `src/governor/ask/prompts/` into `evaluation/reports/PROMPTS_FROZEN.sha256` (sha256sum format, file names only).
5. Write `evaluation/reports/TUNING.md`: what you changed and why, the tune numbers before and after, and which failure categories remain.

Rules: never run `--split holdout` in this step; never edit `evaluation/golden/`; never read golden questions to write prompt examples (the acceptance checks prompts for golden text).

Read: `src/governor/eval/{run,harness,systems}.py`, `src/governor/ask/prompts/*.md`, `NOTES.md`.

Done when `plan/accept/accept_g10a.py` passes.
