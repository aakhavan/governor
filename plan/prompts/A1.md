# A1: Airflow integration (governor side)

Contract: `../airflow-platform/docs/spec.md` §8 (items 1–5) and ADR `../airflow-platform/docs/adr/0001-thin-orchestrator.md`. Rules: this repo's `AGENTS.md`. **Code freeze:** existing files may only gain lines, and only `src/governor/api/app.py` (registration) and `apps/streamlit/client.py` (one helper method) may be touched at all.

Read first: `src/governor/build/__main__.py` (the `profile` subcommand), `src/governor/build/workspace.py` (`build_dsn` env names), `src/governor/api/app.py` (how routes and `caller_role` auth are wired), `apps/streamlit/client.py` and `apps/streamlit/pages/2_Trace_explorer.py` (page style), `docker-compose.yml`, `testbed/README.md`.

Build:
1. `airflow/dags/governor_profile_raw.py`, exactly as spec §8 item 1 says:
   - `dag_id="governor_profile_raw"`, `schedule=None`, `catchup=False`, tags `["governor"]`;
   - one `DockerOperator` task `profile`: image `governor:local`; command `python -m governor.build profile --schema raw --policy knowledge/shop/policy.yaml --out /data/profiles/<run id with ':' replaced by '_'>.json`;
   - a volume mount from the Variable `governor_data_volume` (default: the real volume name; check it with `docker volume ls` and record it in `NOTES.md`);
   - the environment `GOVERNOR_PG_HOST/PORT/DB`, `GOVERNOR_BUILD_USER/PASSWORD` rendered from Variables `governor_pg_host` (default `host.docker.internal`), `governor_pg_port`, `governor_pg_db`, `governor_build_user` and `governor_build_password` with `{{ var.value.get(...) }}`; **no literal password**;
   - `extra_hosts={"host.docker.internal": "host-gateway"}`, `mount_tmp_dir=False`, `docker_url` from the Variable `docker_url` (default `tcp://docker-proxy:2375`), `auto_remove="success"`.

   Imports: airflow, `airflow.providers.docker`, `docker.types` and the stdlib only. **Never `governor`.**
2. `src/governor/api/profiles.py`: `make_router(auth_dependency) -> APIRouter`, with:
   - `GET /profiles`: run ids, newest first, max 100;
   - `GET /profiles/{run_id}`: the stored JSON, unchanged, or 404. `run_id` must match `^[A-Za-z0-9_.+-]{1,128}$`, otherwise 422.

   Both read `$GOVERNOR_STATE_DIR/profiles/` and depend on `auth_dependency`. Never build a path from an unvalidated string.
3. `src/governor/api/app.py`: add the import and one `include_router(make_router(caller_role))` (or the equivalent for how the app is built). At most 3 added lines, none removed.
4. `apps/streamlit/client.py`: add `get_profile(run_id)` and `list_profiles()`, in the style of `get_trace` (additive only). `apps/streamlit/pages/4_Profiles.py` reads the `run_id` query param (`st.query_params`) or offers the list, then shows the summary (tables, rows, relationships) and one table per raw table with the column facts. PII columns are shown exactly as the profile marks them. It never shows more than the API returned.
5. Tests:
   - `tests/test_api_profiles.py`: `test_profiles_router_lists_and_returns`, `test_profiles_router_rejects_traversal`, `test_profiles_router_requires_auth`. Use the app's existing test style and a temporary state dir.
   - `tests/test_airflow_dag.py`: `test_dag_imports_no_governor` (AST), `test_dag_has_no_literal_password`, `test_dag_is_manual_only` (AST: `schedule=None`).
6. `docs/airflow.md`: 15 lines on how the DAG runs from airflow-platform, and the Variables it needs.

Done when `plan/accept/accept_a1.py` passes. It builds `governor:local` from this worktree, runs the profile command in that image against the test bed (which must be up on 55432; if it isn't, stop and say so in `NOTES.md`), and runs the full offline test suite.
