# D5: Gold from catalogue templates, blueprint checks, gap report

Capstone batch 2, step 5. Contract: `docs/capstone/batch2.md` section 10. Human gate: gold numbers are ground truth.

Build:
1. `src/governor/build/gold.py`:
   - `write_gold(target, design, catalogue) -> list[Path]`: for each `build` KPI, `models/marts/<domain>/kpi_<id>.sql` = `catalogue.render(kpi, mapping)` with each relation name replaced by `{{ ref('<model>') }}`, and `_<domain>.yml` with the description, `meta` (`kpi_id`, `owner`, `source_tier`, `source_ref`, `template_sha256` of the KPI's `template_sql`, `rendered_sha256` of the model file) and `not_null` on the grain column (`month` or `cohort_month`; none for grain `total`).
   - `check_project(target, catalogue, policy) -> list[Finding]`: blueprint L1 to L9 statically over the generated project as section 10 (L9: no `CAST`, `::`, `TRIM`, `LOWER`, `UPPER`, `REPLACE` in gold; L7: no policy PII column selected in gold; L8: the model file equals a fresh render from `governor/design.json`, and both hashes match the catalogue and the file). High findings stop the build with status `blueprint_failed`.
   - `write_gaps(target, design) -> Path`: `governor/gaps.md` from the declined KPIs.
2. `graph.py`: after silver, `write_gold`, `check_project`, `dbt build --select marts`, then `summarise` writing `governor/build.json` (models, tests passed, KPIs built with row counts, gaps, model cost). `approve` now ends with `{"status": "built" | "escalated" | "blueprint_failed", "kpis_built", "gaps", "tests_passed", "repairs"}`; blueprint findings carry `rule` (for example `"L9"`), `severity`, `target` and `problem`.
3. Tests in `tests/build/`: rendered gold for every catalogue KPI parses in Postgres dialect; each blueprint rule fires on a crafted bad project; live: the full sample run (fake LLM, fixtures from D3 and D4) builds all eight `build` KPIs, and the five order-level KPIs and the repeat purchase rate equal values computed independently in the test from the sample CSVs.
