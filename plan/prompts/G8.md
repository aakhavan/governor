# G8: Streamlit as a thin client over the API

The UI talks to the governor API (G7) over HTTP only. Pages contain no SQL, no policy, no DuckDB and no `governor.ask` imports.

Build:
1. `apps/streamlit/client.py`: `ApiClient(base_url, token)` with `ask`, `resume`, `list_traces`, `get_trace`, `health`, using httpx. Base URL from env `GOVERNOR_API_URL`; the special value `asgi` uses `httpx.ASGITransport(app=governor.api.app.app)` in-process (tests and single-process demos; the only place the UI may import `governor.api`).
2. `apps/streamlit/app.py`: landing page (what it is, API health, `as_of`) and a token field kept in session state. The role is whatever the API says the token is; there is no role picker.
3. Pages:
   - `pages/1_Ask.py`: question box; answer card (answer text, the result table, SQL in an expander, models, upstream sources, freshness, cost badge); clarify flow with a reply box that calls `resume`; refusals shown as such. `thread_id` in session state, so a rerun keeps a pending clarification.
   - `pages/2_Trace_explorer.py`: filters (outcome), table of the caller's traces, detail view of one trace (plan, SQL attempts with validator codes, policy decisions).
   - `pages/3_Developer.py`: API URL, health, model ids from `/health` or a settings endpoint if you add one; `access.yaml` shown read-only.
4. `docker-compose.yml`: fill in the `ui` service (`GOVERNOR_API_URL=http://api:8000`).
5. Tests in `tests/ui/` with `streamlit.testing.v1.AppTest`, `GOVERNOR_API_URL=asgi`, `GOVERNOR_LLM=fake` and a test token, exact names: `test_ask_page_answers_with_fake_llm`, `test_ask_page_clarify_flow`, `test_trace_explorer_lists_rows`, `test_developer_page_renders`, `test_no_token_shows_login_hint`.
