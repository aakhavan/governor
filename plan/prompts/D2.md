# D2: Profile the raw schema

Capstone batch 2, step 2. Contract: `docs/capstone/batch2.md` section 5. Deterministic: no model calls.

Build:
1. `src/governor/build/profile.py`: `profile_schema(dsn: str, schema: str = "raw", policy: dict[str, str] | None = None) -> dict` returning exactly the section 5 structure:
   - per table: row count; per column (skip names starting with `_`): `inferred_type` from the values (integer, numeric, timestamp, date, boolean, text; empty strings count as null), `null_rate`, `distinct`, `pii` (column name in the policy), `min`/`max` only for non-PII integer, numeric, timestamp and date columns, otherwise null;
   - `candidate_keys`: single columns with no nulls and `distinct == rows`; column pairs only for tables without a single-column key;
   - `relationships`: same-named columns across tables whose non-null distinct values are found in another table's candidate key column with coverage of at least 0.95.
   - Work in SQL (aggregates on the server), so a 1-million-row table profiles in seconds; never fetch a PII value into Python.
2. `src/governor/build/models.py`: Pydantic models for the profile (the rest of the file grows in D3).
3. CLI: `python -m governor.build profile --schema raw [--policy knowledge/shop/policy.yaml] [--out <file>]` as the build login; prints the profile JSON as the last line (or writes `--out` and prints a one-line summary).
4. Tests in `tests/build/` (live, skip without the database): on the synthetic sample the orders key is found, the customers table's `customer_id` is a key while `customer_unique_id` is not (the sample has a customer with two ids), `olist_orders_dataset.customer_id` relates to `olist_customers_dataset.customer_id`, types are inferred (purchase timestamp is `timestamp`, price is `numeric`), and no PII value appears anywhere in the output. Offline tests for type inference on sample strings.
