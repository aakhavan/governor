# C4: Postgres adapter and database roles

Capstone batch 1, step 4. Contracts: `docs/capstone/design.md` §3 (adapter) and §4 (roles).

Build:
1. `src/governor/core/adapters/postgres.py`: `PostgresAdapter` with psycopg 3, DSN from env `GOVERNOR_PG_DSN`, `dialect = "postgres"`. Every connection is read-only (`SET TRANSACTION READ ONLY` or the session default), applies `statement_timeout` from the call's `timeout_s`, maps a cancelled statement to `QueryTimeout` and any other database error to `QueryError`, fetches at most `row_cap` rows, returns JSON-safe values, and always closes. `dry_run` uses `EXPLAIN`. `list_columns` reads `information_schema.columns`. Register it in `get_adapter("postgres")`.
2. An optional `role` argument on `run` and `dry_run`: when given, the adapter runs `SET ROLE <role>` after connecting and refuses role names that are not in the `allowed_roles` list passed at construction (`get_adapter("postgres", allowed_roles=[...])`), raising `QueryError` before any SQL runs. The role always comes from the caller (later the token), never from SQL text.
3. `testbed/sql/roles.sql`, idempotent, applied by the admin: `governor_ask`, `governor_analyst`, `governor_finance_admin`, `governor_build` exactly as in design §4, schema `dev_governor` with CREATE for `governor_build` only, schema `private` for the admin only. Login passwords come from psql variables set from env, with the local defaults named in the design.
4. `testbed/apply_roles.py --dsn <admin dsn>` runs `roles.sql` with the passwords from env.
5. Postgres cases in `tests/core/test_adapter_conformance.py` run against a small `conformance` schema the tests create as admin (env `GOVERNOR_PG_ADMIN_DSN`) and grant to `governor_ask`; they skip when the variables are unset.

Read: `src/governor/core/adapters/`, `docs/capstone/design.md` §3 and §4, `testbed/`.

Done when `plan/accept/accept_c4.py` passes. It starts the compose stack, applies the roles and checks isolation at the database level; Docker Desktop must be running.
