# D3: Design proposal, validation, report and the design gate

Capstone batch 2, step 3. Contract: `docs/capstone/batch2.md` sections 6 to 8; catalogue API in `src/governor/core/catalogue.py`.

Build:
1. `src/governor/build/models.py`: Pydantic models for the design proposal exactly as section 6 (silver models, columns, KPI decisions with mapping or reason and gap, assumptions).
2. `src/governor/build/design.py`:
   - `propose(profile, catalogue, blueprint, approved, llm, findings=None) -> Proposal`: one structured call to the plan model with `prompts/propose.md`. The prompt gives the profile (PII columns as names and counts only), the blueprint rules, the catalogue (ids, definitions, relations, inputs, requires), approved decisions and, on a repair, the previous findings. It never contains raw data values.
   - `validate(proposal, profile, catalogue, policy) -> list[Finding]` with every code in the section 6 table; a finding names the code, the model or KPI, and the problem.
   - `render_report(proposal, findings, thread_id) -> str`: the section 7 report.
3. `src/governor/build/graph.py`: the build `StateGraph` up to `record_decisions` (section 8): profile, propose, validate (at most 2 repairs, then `design_invalid`), write_report (writes `governor/design.json` and `governor/design.md` in the target), `design_gate` with `interrupt()`, reject with a note (one extra propose), approve, `record_decisions` (appends the approved KPI mappings as `column_mapping` decisions, with approver and date, to `<target>/governor/approved.yaml` in the design.md section 8 format). SQLite checkpoints in `GOVERNOR_STATE_DIR`. Models from `GOVERNOR_BUILD_PLAN_MODEL` / `GOVERNOR_BUILD_WRITE_MODEL` through `governor.core.llm`; the fake LLM via `--llm fake:<script.json>` with the section 8 script format (reuse the pattern in `src/governor/ask/llm_testing.py`; do not import from `governor.ask`).
4. CLI: `run`, `approve` and `reject` as in section 8. In D3, `approve` ends with status `design_approved`.
5. `tests/fixtures/build/sample_design.json`: a valid proposal for the synthetic sample that builds `gmv`, `net_revenue`, `aov`, `on_time_delivery_rate`, `avg_review_score`, `repeat_purchase_rate`, `cohort_retention` and `historical_clv`, and declines `conversion_rate` and `gross_margin` with gaps. Silver: staging models for orders, order items, customers and reviews, plus `int_order_lines`, `int_orders` and `int_order_reviews` (latest review per order).
6. Tests in `tests/build/`: each validation code fires on a minimal bad proposal; the report has every section; the graph pauses at the gate, resumes after approve and after reject in a new process (live tests skip without the database).

Read: `docs/capstone/batch2.md` sections 6 to 8, `knowledge/kpis.yaml`, `knowledge/blueprint.md`, `knowledge/shop/policy.yaml`, `src/governor/core/catalogue.py`, `src/governor/core/llm.py`, `src/governor/ask/graph.py` (interrupt and resume pattern only).

Done when `plan/accept/accept_d3.py` passes; Docker Desktop must be running.
