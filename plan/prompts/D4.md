# D4: Silver writer, dbt build in the dev schema, repair and escalation

Capstone batch 2, step 4. Contract: `docs/capstone/batch2.md` sections 8 and 9. Human gate: this step writes to the database.

Build:
1. `src/governor/build/silver.py`:
   - staging SQL generated by code from the approved design: `select <expr> as <name>, ... from {{ source('raw', '<table>') }}`;
   - intermediate SQL from the write model with `prompts/intermediate.md` (given the model's description, its refs and their declared columns, and its own declared columns; never data values);
   - `check_sql(model, sql, design) -> list[str]` before dbt: exactly one SELECT (sqlglot, Postgres dialect, after replacing Jinja calls with identifiers), only `{{ ref('<declared ref>') }}`, no `source()` in intermediate, no DDL or DML;
   - `_staging.yml`, `_intermediate.yml` and singular tests as section 9 (PII meta, key tests, composite keys in `tests/`);
   - `build_silver(target, design, llm) -> SilverResult`: write files, `dbt build --select staging intermediate` through `run_dbt`, then compare each model's columns with the design via `information_schema` in `dev_governor`; a failing model goes to `prompts/repair.md` with its error and SQL, at most 2 repairs with the write model, then one try with the plan model, then status `escalated` naming the model and the last error.
2. `graph.py`: after `record_decisions`, `write_silver` and `dbt_build_silver` with that repair loop; `approve` now ends with `{"status": "silver_built" | "escalated", "models", "tests_passed", "repairs"}` (`repairs` = number of repair calls made) (D5 extends it to gold).
3. `tests/fixtures/build/sample_silver.json`: a fake script part with the intermediate SQL for the sample design, plus a second entry for `int_order_lines` whose first draft fails dbt (a wrong column name) and whose repair is correct.
